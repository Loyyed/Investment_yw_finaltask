# 课程要求、披露地图与工具选择

有具体课件/合同才采用其阶段及验收规则，以下是既有工作中可复用的结构，不预填新公司的课程成果或个人答卷。

| 实际任务类型 | 通用结构 | 核准与交付重点 |
| --- | --- | --- |
| 第一次定位 | 合并利润表/附注等指标版本、单位、期间和主体定位 | 检索过程和交叉位置；原文核对不等于经营原因确认 |
| 第二次结构化提取 | 多年业务/产品/地区/渠道原值、合计与范围 | 字面原值、来源绑定、合计冲突；不混不同切面 |
| 第三次口径识别 | 候选清单、采用/排除理由、真实初选与修正 | 原值真实与研究用途分开，不编造修正历史 |
| 第四次变化核验 | 两期原值、七项可比性、公式、舍入与报告披露同比 | 原值和比较、计算结果分别核准，重述不混接 |
| 初步研究卡 | 一个与用户选择匹配的题目、事实/解释/Unknown/反方 | 不为“全面”同时套所有可选题；投资判断需目的与依据 |
| 披露地图 | 公司业务、经营讨论、资产负债表、利润表、现金流、附注、审计、治理/关联/风险 | 每类能回答与不能回答什么，流量与时点余额区分 |
| 商业模式与优势证据 | 三维问题、矩阵、经济图、优势链、真实Fact/Unknown核验 | 机制可反证；后续财务检验与签署责任单列 |

审计意见、关键审计事项和治理风险提供财务责任/风险线索，不能当投资回报保证。披露地图写明确页码/版本，不仅写“财务报告部分”；首次读材料可建章节索引，后续按问题定位，不每次全文重读。

工具组件按用途选择：格式技能用于实际文档/图表读取与渲染，Python用于可复算处理，本地窗口用于真实核准，Git保存版本。现有环境足够时不加插件；外部数据/MCP/新工具只有在任务需要且授权覆盖时使用。需要独立审阅时如实记录身份，同一Agent反方自查不能声称独立Reviewer。

反方自查覆盖：范围相加错误、集团/归母/母公司替代、重述、单位错列、长期工艺、品牌因果、渠道净收益、现金与资本回报、行业分母以及未披露风险。写具体来源和处理，而非通用“风险较大”。

若课件要求学生个人反思/Exit Ticket，只提供已做动作、真实修正和待核问题索引，个人判断与签认由学生实际完成；不把Agent文本冒充个人亲历。材料没提供的合同编号/作业不自造验收。
