# 从材料到报告的操作路径

2026-10-13。新版界面属于本目录的“投资学公司分析通用工作台”，公司工作空间作为独立研究项目或连接对象。双击根目录的启动工作台.cmd进入；核心运行仅需Python 3.10以上和标准库。

## 初学者的第一轮操作

1. 左侧新建公司，填写名称与研究类型；已有资料和核验历史可选择“连接已有空间”。新公司不继承其他公司的数据、授权、判断或签名。
2. 进入“材料与来源”，选择文件或资料目录，标注材料角色和用途。原件归档并记录SHA；文字缓存只作定位，不能替代原文核验。
3. 进入“事实核验”，从原件登记一个候选，填写数值、来源页码／字段、期间、单位、主体、范围和定义。默认Unknown。本人打开原件核对后再确认；已有有效Fact不重复确认。
4. 进入“计算与情景”，选择当前有效的输入。同比逐项核对七项可比性；毛利率、比率、差额和合计明确输入顺序、分母与换算。计算候选单独核验，不因原数通过自动成为Fact。
5. 进入“研究与合同”，记录总判断及经营、财务、行业、叙事、预测、估值和风险意见。研究命题写支持、挑战、替代解释、失效条件及证据编号；意见保持Interpretation或Forecast。实际合同逐条建立执行状态和对应底稿，验收与Fact分开。
6. 进入“报告与交付”，生成当前报告。系统汇编实际证据、公式、意见、情景、来源和Unknown，生成Markdown、可打印HTML及依据JSON快照。阅读当前报告，再确认内容；最后按实际姓名、日期和授权记录签署。同人执行／复核会明确注明。

新手视图一次呈现一张核验卡。熟练视图提供证据表格、检索和本项目Agent核准授权入口。未核候选不要求全部确认，由研究问题与实际合同决定必要性。

## 课件方法如何落实

| 研究环节 | 方法 | 操作与边界 |
| --- | --- | --- |
| 公司、证券与时点 | 区分公司经营价值、证券权利和市场价格 | 明确信息截止、权益／股数和研究目的；缺价格或权利不输出买卖决定 |
| 披露定位与口径 | 版本、位置、期间、单位、主体、范围、定义 | 来源卡、核验卡及SHA绑定；缓存只用于定位 |
| 跨年比较 | 原报、重述、分类与年度重大变化 | 七项可比性、停算项、双口径保留与修正底稿 |
| 商业模式 | 收入、成本、资本、现金四环 | 经营编辑器与相匹配的输入计算；利润与现金分开 |
| 行业与竞争优势 | 范围、阶段、格局、机制、风险五步 | 研究命题、反证与缺口；没有分母不算市场份额 |
| 叙事核验 | 原话与解释分开，支持／挑战／替代解释 | 用证据编号连接可观察变量，机制仍需人工判断 |
| 预测与估值 | 明确现金流、增长、折现与永续假设 | FCFF情景逐年保存算式、输入、现值与结果；全部未来层保持Forecast |
| 交付与协作 | 合同验收、内容审阅、签署、交接分别保存 | 版本报告、依据快照、签署收据、work与evidence中间产物 |

第五次综合及拆分合同可并行录入，原一至七课堂最低检查点不能代表完整验收。通用计划不冒充已发布合同；文件齐备、签名或模型跑通不证明事实和因果。

## FCFF情景的适用范围

本轮实现确定性的简化FCFF折现：基期FCFF（人民币元）、预测期统一增长率、1—15年期限、WACC、永续增长、净债务（人民币元）与证券股数（股）。选择Fact作为基期时需明确FCFF定义、人民币元币种口径，并由本人核对；手动基期保持假设。模型不从净利润或CFO自动补出FCFF，不默认填折现率、增长率、债务或股数。

逐年现金流和折现值、企业情景值、股权情景值及每股结果可复查；不是目标价、Fact或买卖结论。基期撤回、绑定或计算引擎改变会提示重算。负FCFF企业、金融企业的适配、分段增长、非经营资产和完整资本结构需另建模型，不以本简化模型宣称已完成。

## 既有工作空间如何连接

本工作台识别普通独立项目（project.json）与原ReviewStore工作空间。原工作空间在独立Python进程中调用原facts()、change_facts()及已有独立核验域，不复制到新事实账本。保留原actor与时间、合同版本、签署和修正历史。

原工作空间的核验仍在其原窗口完成，网页可按本人点击打开。原研究成果可阅读并在新报告中按原状态汇编；新增报告不继承旧内容确认或签名。连接信息及原项目报告汇编放通用根目录runtime，默认不进入工具Git。

## 产物和复用

普通项目的研究草稿在work/report-draft.json，合同执行在work/workbench-contracts.json，情景底稿在work/model-scenarios.json；实际编辑和签署事件进入原有事件链。报告在outputs/workbench-reports，以内容与依据摘要命名，每个版本保留MD、HTML、JSON。签署绑定实际已审阅版本，收据单独导出。

报告或依据变了，内容确认与签署按绑定失效；当前导出入口要求重新生成，历史文件仍保留。依据快照只记录生成时状态，后续Fact必须重新读取当前ReviewStore。材料原件不会因报告导出自动上传。

无需额外大模型密钥。界面支持人工录入、确定性计算、研究编辑和报告组装；深入阅读与机制研究可将“复制Agent协作指令”交给实际使用的Agent继续。

## 熟练用户与Agent命令

```text
python workbench.py link --directory 已有公司目录 --name 公司名称
python workbench.py draft --project 公司目录 --file 研究草稿.json
python workbench.py model --project 公司目录 --file 情景输入.json
python workbench.py report --project 公司目录
python workbench.py series-audit --source 数据.csv --cutoff 2024-12-31 --output 新检查.json
```

draft与model输入结构对应companybench/workflow.py。这些命令不新增人工核准、内容通过或签名；核验与代理授权仍用原有真实接口。跨Agent通信优先传递编号、版本、来源位置和中间产物路径，不全文重读日志。
